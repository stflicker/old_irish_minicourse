# Usage and setup (v0.4)

## Daily use

1. Around 08:00–09:00 **Japan time**, a ChatGPT scheduled task sends a notification with the day's lesson or a link to its HTML page (after a Pages URL has been configured).
2. Open the lesson, read Stifter's cited section, and complete the two short quiz questions.
3. Click **Mark complete**. The page saves the result in **that browser**.
4. Send the record row to ChatGPT (via **Copy record**) or download a Markdown export. A reply such as `D001: done; 12m; difficulty 2/5` is enough to confirm completion.

`published` means an HTML lesson was made available, **not** that you studied it. Missed lessons stay incomplete until you report them.

## What must be connected for *fully automatic* HTML delivery and MD updates

**GitHub is recommended** because it provides static website hosting and a versioned Markdown repository without a custom server.

1. **GitHub is connected** in the current ChatGPT conversation, but no repository is accessible yet. Create an empty repository such as `old-irish-microcourse` (public is simplest); initialise it with a README and give ChatGPT its exact URL. ChatGPT can then try to write the source files using the connector. If workflow-file writes are not permitted through the connected app, upload `.github/workflows/daily-publish.yml` yourself.
2. Transfer the package contents into that repository, preserving paths, including `.github/workflows/daily-publish.yml`, `lessons/`, `docs/`, and `scripts/`. Keep `FIRST_28_DAYS.md` unchanged.
3. Open **Settings → Pages → Build and deployment → Source** and select **GitHub Actions** (NOT "Deploy from a branch"). Our workflow directly deploys the `docs/` artifact. Branch-based publishing is unreliable here because commits made using `GITHUB_TOKEN` do not trigger a fresh Pages build.
4. Under **Settings → Actions → General → Workflow permissions**, permit writing to the repository (**Read and write permissions**, if the setting is offered). Enable Actions if prompted.
5. Run **Actions → Old Irish daily publication → Run workflow** once. Verify a successful deployment and a working Day 001 page. Unwritten days show transparent "not yet published" placeholders.
6. Supply ChatGPT the GitHub repository URL and the published Pages URL. The daily task can then be updated to read the live Markdown and send a real clickable URL such as `.../days/001.html`.
7. Confirm the GitHub connection actually allows reading and writing repository files from a scheduled task. Depending on permissions or approval requirements, tasks may pause rather than making unattended changes. If that happens, the chat delivery remains a fallback.

The GitHub Action is scheduled around **07:20 JST**, records `published` / `awaiting_content` in `PROGRESS.md`, commits any changes, and deploys the interactive pages **directly** to GitHub Pages. GitHub may delay scheduled workflows, so the morning push should verify availability rather than assume it.

The actual grammar for an unprepared day is **not** generated by the GitHub Action. The future ChatGPT job will have to author and commit its Markdown first; or you can add the Markdown manually. We deliberately avoid publishing AI-invented declensional forms simply to fill a schedule.

## Progress: what is and isn't automatic

| Event | Source | Result |
|---|---|---|
| A new date arrives | GitHub Action | Adds `OI-D###` with `published` if the lesson Markdown exists, otherwise `awaiting_content` |
| You answer on the HTML page | Browser | Saves completion locally and enables a `PROGRESS.md` export |
| You report completion in ChatGPT | Chat reply | The assistant can check and, **if GitHub write access is connected**, update the repository's `PROGRESS.md` |
| You export a Markdown record | Browser | Downloads a personal copy; it does not overwrite GitHub |

The local viewer records minutes, 1–5 difficulty, and one optional note. No vocabulary database or extra metrics are required.

**Privacy:** A public GitHub repository makes `PROGRESS.md` and any notes in it visible. To avoid publishing personal notes, keep the repo's delivery records minimal and store private study notes in ChatGPT or a local exported record. A private GitHub repository with Pages may depend on your account/plan; don't assume Pages output will be private.

## No GitHub yet?

You can still use [docs/index.html](docs/index.html) or [docs/days/001.html](docs/days/001.html) locally. The HTML quiz works without a server when opened in a normal desktop browser; some phone file viewers block JavaScript.

The existing ChatGPT daily task remains the **lesson delivery fallback** and can send the content in chat. It cannot reliably update a downloaded local `.md` or read files attached to this Project during a scheduled run. To meet both *hosted HTML every day* and *automatic persistent record updates*, finish the repository connection first.

## Technical maintenance

- Edit `FIRST_28_DAYS.md` only if we explicitly agree to change the syllabus. The current first 28 topics are fixed.
- Add verified content using `LESSON_TEMPLATE.md` as `lessons/OI-D002.md`, etc.
- Build locally: `python -m pip install -r scripts/requirements.txt` followed by `python scripts/build_site.py`.
- Test a date without affecting the real record: use a throwaway copy of the repository, then `python scripts/daily_publish.py --today 2026-10-10`.
- To add completion after a learner reply, use `python scripts/update_completion.py OI-D001 --minutes 12 --difficulty 2 --note 'Done'` and commit `PROGRESS.md`.
- After Day 028, extend the day-by-day schedule before expecting further HTML pages; `CURRICULUM.md` is a unit map, not a numbered daily sequence.

## Why a repository is needed

Without a persistent repository, the ChatGPT task can send lesson text, but cannot guarantee a lasting updated `PROGRESS.md` or host the browser UI. There is still no need for a paid server or database. The browser's **Mark complete** button is local only; permanent completion requires sending your record to the ChatGPT conversation so it can be entered into the repository. The daily scheduled *publication* entry is automatic, but completion isn't inferred.
